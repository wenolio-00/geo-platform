主链路泳道图

诊断报告 内容优化 手动复检

一、诊断报告

从品牌配置创建诊断任务，经 QuerySet、平台巡检和聚合，产出 report_data_v1 与 Dashboard 快照。

Input 输入入口资产
  • 品牌配置brand_config_id / BrandConfigCreate定义诊断对象、别名、行业、主题和竞品范围。
  • 诊断任务参数queryset_policy / inspection_mode / platforms决定问题集策略、巡检模式和目标平台。
  • 生成约束generation_constraints控制候选问题数、active query 门槛和调试小样本。
Process 处理核心函数
  • 创建诊断任务geo.py:post_diagnostic_run → inspector.py:create_run先持久化 queued run，再异步调度 run_diagnostic_job。
  • 解析 QuerySetinspector.py:resolve_queryset / queryset.py:generate_queryset优先复用 frozen QuerySet；否则生成、过滤、治理并冻结。
  • 平台巡检与聚合_inspect_queries → aggregate_report调用平台客户端，解析 mentions/citations，聚合为报告数据。
Output 输出沉淀结果
  • 诊断报告数据report_data_v1 / report_data前端报告页、HTML 导出和后续内容优化的核心输入。
  • 巡检原始结果inspection_results.json保留每条 query × platform 的原始回答、解析结果和失败信息。
  • Dashboard 快照brand_dashboard_snapshots.json把完成报告转成 dashboard/content generation 可消费的上下文。

二、内容优化

只覆盖当前工程链路：读取诊断快照上下文，生成优化草稿，保存内容版本，记录反馈与归因占位。

Input 输入诊断上下文
  • Dashboard 合约get_dashboard_contract()提供最新诊断报告、指标、优化动作和规则上下文。
  • 优化动作与规则action_id / rule_id确定本次内容要解决的问题、对应规则和目标意图。
  • 内容模板content_templates.py:template_context选择适合的内容结构、素材覆盖和模板版本。
Process 处理核心函数
  • 构建生成上下文get_content_generation_context把诊断结论、QuerySet 摘要、lineage、规则和版本历史整理给前端。
  • 生成优化草稿generate_optimized_draft_async校验 action/rule/template 后调用内容生成任务。
  • 保存内容版本_persist_content_version保存 draft、baseline_run_id、report_id、queryset、lineage，并创建 attribution 记录。
Output 输出版本资产
  • 内容版本content_versions.json / content_version_id一次优化内容产物，可追踪版本、父版本和生成来源。
  • 用户反馈content_feedback.json / feedback_summary记录 helpful / not_helpful，并回写到内容版本和归因记录。
  • 归因占位effect_attribution.status = awaiting_retest等待用户手动复检产生 comparison_run_id 后再计算效果变化。

三、手动复检

复检不是新系统，而是用户再次创建 DiagnosticRun；完成后用基线 run 和对比 run 计算效果归因。

Input 输入对比条件
  • 基线诊断任务baseline_run_id内容优化前的完成态诊断报告，来自内容版本保存时的 latest_run_id。
  • 复检任务参数queryset_policy / queryset_change_reason用户手动创建新 run 时决定是否复用问题集和说明复检原因。
  • 内容版本content_version_id把本次优化产物与后续效果对比绑定。
Process 处理对比逻辑
  • 创建对比 runPOST /diagnostic-runs用户手动触发新的诊断任务，流程仍走 run_diagnostic_job。
  • 查找对比任务_latest_comparison_run_id若未显式传 comparison_run_id，自动找 baseline 之后最新完成 run。
  • 计算效果归因compute_content_effect_attribution → _effect_delta / _comparability对比优化前后指标变化，并判断 QuerySet 是否可比。
Output 输出复检结论
  • 对比诊断报告comparison_run_id / report_data优化后的新诊断报告，是效果计算的后测样本。
  • 效果变化effect_delta对 visibility、rank、sentiment、recommend_score 等指标做 before/after/delta。
  • 可比性判断comparability.same_queryset / confidence说明两次诊断是否使用同一问题集或同源问题集。
诊断报告沉淀 report_data + dashboard snapshot → 内容优化消费诊断上下文并保存 content_version → 用户手动复检生成 comparison run 并计算 attribution

关键数据资产与存储

中文业务名优先，工程变量用于定位代码

品牌配置

brand_configs.json
保存 entity、aliases、topics、competitors，是诊断对象与内容生成上下文的起点。

诊断任务

diagnostic_runs.json
保存 run 状态、QuerySet snapshot、quality gate、report_data 和失败排查字段。

问题集资产

querysets.json
保存 frozen QuerySet；queries[] 是 active-only，query_candidates[] 是审计全集。

巡检结果

inspection_results.json
保存每个平台回答、解析 mention/citation、错误类型和 raw answer。

Dashboard 快照

brand_dashboard_snapshots.json
由完成报告派生，供 dashboard 与内容优化读取。

内容版本

content_versions.json
保存生成草稿、模板、baseline_run_id、lineage、版本号和父版本。

内容反馈

content_feedback.json
保存 helpful / not_helpful 信号，并更新 feedback_summary。

效果归因

effect_attribution.json
保存 baseline/comparison run、effect_delta、comparability 和归因状态。

关键接口清单

按业务阶段分组，不按路由文件顺序
业务阶段 业务动作 接口 / 函数 输出与意义
诊断报告 创建品牌配置 POST /api/v1/geo/brand-configs 返回 brand_config_id，作为诊断任务输入。
诊断报告 创建诊断任务 POST /api/v1/geo/diagnostic-runs 返回 run_id，后台异步执行 QuerySet、巡检和聚合。
诊断报告 查询任务状态 GET /api/v1/geo/diagnostic-runs/{run_id} 读取 queued/running/aggregating/completed/failed/interrupted 状态和失败调试字段。
诊断报告 读取报告数据 GET /api/v1/geo/diagnostic-report?run_id=... 读取完成态 report_data_v1，用于页面展示和导出。
内容优化 读取生成上下文 GET /dashboard-contract + get_content_generation_context 提供 action/rule/queryset/lineage/template 信息。
内容优化 生成内容草稿 POST /api/v1/geo/content/generate 返回并保存 content_version_id，同时创建 awaiting_retest 的归因记录。
手动复检 计算效果归因 POST /content/versions/{id}/effect-attribution 对比 baseline 和 comparison run，输出 effect_delta 与 comparability。

研发排查视角

优先看链路断在哪个资产

诊断报告失败

  • 先看 diagnostic_runs.json 的 status、message、error。
  • QuerySet 失败看 last_queryset_quality_report、attempt reports、candidates preview。
  • 平台失败看 inspection_quality_gate 与 inspection_results.json。

内容优化没有上下文

  • 检查是否已有 completed diagnostic run。
  • 检查 brand_dashboard_snapshots.json 是否已由报告同步生成。
  • 检查 action_id / rule_id 是否存在于最新 dashboard contract。

复检归因未计算

  • 状态为 awaiting_retest 表示尚无完成态 comparison run。
  • 优先使用 reuse_latest 保持 QuerySet 可比。
  • 对比结果看 effect_delta 与 comparability.confidence。
